# Fan Control Core

笔记本风扇的控制核心。**一个接口，四个动作，谁都能用。**

```
{"op":"describe"}                    这台机器有几个风扇、走哪条通道、能不能写
{"op":"read"}                        现在转速多少、占空比多少
{"op":"set","fan":0,"percent":60}    把这个风扇固定在 60%
{"op":"boost","fan":0}               全速
{"op":"auto","fan":0}                交还给固件自己管
```

每个风扇会报一个 `supportsDuty`。**有的通道只有"全速"和"自动"两档**，
那种通道上 `set` 会**明确拒绝**，而不是收到 60% 就给你 100% ——
给一个和请求不一样的值却说成功，是这类工具最容易骗人的地方。

标准输入一行一条 JSON，标准输出一行一条 JSON。调用方不需要知道这台机器
是 ASUS 的 WMI、Dell 的 SMM、还是同方公版的 EC —— 那是这个核心的事。

## 为什么不按品牌分

按"品牌/主板"分类会得到一个永远补不完的驱动库。真正稳定的分类是**控制通道**：

| 通道 | Windows | Linux | 什么时候用 |
| --- | --- | --- | --- |
| hwmon | — | `/sys/class/hwmon` | Linux 第一优先。内核已经导出可写 PWM 就直接用 |
| WMI / ACPI | OEM WMI / ACPI | 厂商内核驱动 + sysfs | 现代 OEM 主路径，Windows 第一优先 |
| HID | HIDClass | hidraw | Razer 这类；协议天然跨平台 |
| Raw EC | PawnIO | 专用 kmod / ec_sys | **只做兜底**，必须匹配固件指纹 |
| SMM | 专用实现 | `dell-smm-hwmon` | Dell 特殊路径 |

要维护的资产是**协议/机型 profile 数据库**，不是品牌驱动。

平台策略（静音/均衡/性能）**不在这里** —— 那些同时改功耗、温度目标和声学策略，
和"把这个风扇设到 60%"不是一回事，混在一层只会让两边都说不清。

## 安全规则（不可协商）

1. **同一时刻只有一个后端拥有写权限。** 两个后端同时写风扇，结果是谁也不知道现在是谁说了算。
2. **有固件接口就不写 Raw EC。** WMI/ACPI 能做的事不绕到 EC 去做。
3. **Raw EC 必须匹配固件指纹。** 认不出的机器默认只读 —— 往陌生 EC 寄存器里写是要烧硬件的。
4. **退出即恢复。** 程序退出、崩溃、服务停止，都把风扇交还固件的自动模式。
   一个把风扇停在 20% 然后退出的程序，会把机器烤了。
5. **一切写入有硬边界。** 占空比、转速目标、曲线点都夹在机型 profile 声明的范围里。
6. **许可证隔离。** 寄存器映射和协议是事实，可以重新实现；直接复制源码前逐项审查许可证。

## 现在做到哪儿

| 通道 | 读转速/占空比 | 任意占空比 | 全速 / 自动 |
| --- | --- | --- | --- |
| Uniwill / Tongfang（同方公版，含机械革命等）WMI EC | **实测可用** | 还不行，见下 | **实测可用** |
| Linux hwmon | 已实现 | 已实现 | 已实现 |
| 其余通道 | 未实现。接口已经留好，加一个后端不改核心 | | |

Linux hwmon 那一条没有在 Linux 上实测过。

Uniwill 那条通道**目前给不了任意占空比**：`0x0751` 的那一位在固件里叫"全速模式"，
字面意思就是全速 —— 置位之后两个风扇都拉满，写多少占空比它都不看
（实测要 70% 得到的是 100%）。真正的任意占空比要走自定义风扇表
（`0x0F20`/`0x0F50` 加 `0x07C5`/`0x07C6` 的使能位），还没做。
所以现在如实报 `supportsDuty: false`。

本机实测（MECHREVO / Uniwill，两个风扇）：读到 2700 转 / 44% 占空比；
`boost` 之后两个风扇 4700 转 / 100%；`auto` 之后回落到 2860 转 / 47%。

覆盖面靠的是 profile 数据库长起来，不是核心变复杂。

## 构建

```
dotnet build src/FanControlCore/FanControlCore.csproj -c Release
```

Windows 上的 Raw EC 通道需要管理员权限。
